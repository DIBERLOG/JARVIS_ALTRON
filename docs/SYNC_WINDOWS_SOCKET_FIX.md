# Windows Sync v2: обрыв первого запроса Android после QR

Пользователь подтвердил, что VPN телефона был отключён, а ошибка `unexpected end of stream` возникла после сканирования QR-кода.

## Причина и исправление

Слушающий TCP-сокет службы обмена работает в неблокирующем режиме для остановки службы. На Windows принятые соединения наследовали этот режим. Обработчик TLS использует синхронные чтения с таймаутами, но не переводил принятый сокет в блокирующий режим. Первое чтение могло завершиться `WSAEWOULDBLOCK`, код 10035, и соединение закрывалось до HTTP-ответа.

В `lan_sync::connection` принятому сокету явно задан `set_nonblocking(false)` до настройки таймаутов и создания TLS-потока. Режим слушающего сокета, проверка частных адресов, лимит соединений, дедлайны, ограничения запросов, аутентификация и шифрование не менялись.

## Проверка реального транспорта

Добавлен отдельный игнорируемый Rust-тест `android_tls_pairing_wire_fixture` и opt-in Android instrumentation `WirePairingTests`. Сервер привязан только к localhost; сертификат, секрет, временный профиль и имя телефона вымышленные. Android-эмулятор обращается через адрес хоста `10.0.2.2`. Реальный профиль ПК и физический телефон не используются.

До исправления тот же серверный обработчик воспроизвёл отказ первого TLS-чтения: 0 прочитанных байт и ошибка Windows 10035. После исправления настоящий `SyncClient.request` на подписанном Android release 1.1.11 успешно выполнил запрос сопряжения по прямой Wi-Fi сети и обычному маршруту Android. Для каждого маршрута проверены HTTP 202 на верный секрет, HTTP 401 на неверный секрет и отказ TLS на неверный отпечаток. Шесть соединений создали ровно два вымышленных запроса сопряжения, без дублей. Rust и Android проверки завершились успешно.

Шесть серверных проверок LAN также прошли: авторизация, разрешённые команды и повторы, объединение независимых правок, удаление/правка, ограничения адресов и сейфа, три временных профиля с обменом, ротацией и отзывом. Временная тестовая запись Windows Credential Store удалена после проверки. GUI release собран.

Это проверка сетевого транспорта и запроса сопряжения; она не заменяет пользовательскую проверку роутера, физического телефона, подтверждения устройства и полного обмена его данными.

## Выпуск и повторная проверка

Исправленный EXE с прежними DLL и ресурсами подготовлен по пути:

`artifacts/sync-v2-lab/windows-1.1.0-instructions/JARVIS-Sync-v2-LAB-Connection-Fix.exe`

Старый EXE сохранён в `target/JARVIS-Sync-v2-LAB-before-socket-fix.exe`. При штатном перезапуске выявлен отдельный отказ расшифровки текущего LAB-профиля. Проверен и прежний EXE: он также завершается с отказом расшифровки. Прежний EXE возвращён на прежний путь. Настройки не сбрасывались, зашифрованные файлы не заменялись и ключи реального профиля не перезаписывались. Изменение сетевого сокета не меняет формат хранения или криптографический контекст. Точная причина отказа профиля пока не установлена. Пользователь подтвердил наличие копии восстановления и пароля; ожидается путь к копии для отдельной проверки и подготовки восстановления. Дополнительная байтовая копия защищённых файлов журнала и группы сохранена в локальном `target/protected-profile-before-recovery-*`.

Стабильный Windows 1.0.0 и установщики старых выпусков не заменялись. До восстановления доступа к профилю повторное сопряжение на этом ПК заблокировано. Исправленная сборка проверена на временном профиле, но успешный запуск текущего пользовательского профиля не подтверждён.

На телефоне оставить APK 1.1.11. После восстановления доступа к LAB-профилю на ПК включить обмен, создать свежий QR, отсканировать его телефоном и одобрить устройство на ПК. Первую проверку провести без VPN; потом отдельно проверить с VPN и разрешением локальной сети.

# Экспериментальная адаптация платформ

Подготовлены исходники и рецепты нативных установочных пакетов. До успешной сборки и проверки на соответствующих машинах это не подтверждённая поддержка новых ОС. Android не запускался на устройстве. Windows остаётся основной проверенной средой.

## Linux и macOS

Общими остаются Rust-ядро, интерфейс Tauri/Svelte и данные Центра. Добавлены поиск ресурсов вне Windows, выбор нативной библиотеки Vosk, системная озвучка и открытие файлов в проводнике. Сайты открываются через `xdg-open` / `open`. Команды Calculator, Telegram, Discord, VS Code и Steam используют платформенные варианты; приложение должно быть установлено. На Linux калькулятор выбирается из `gnome-calculator`, `kcalc`, `galculator`.

Windows-сценарии AutoHotkey, завершение процессов через taskkill и известные Windows-only команды исключаются из каталога на других ОС. Это не делает все оставшиеся сценарии автоматически переносимыми.

### Подготовка и запуск

Нужны Rust/Cargo, Node.js/npm, инструменты нативной сборки и **Vosk для своей ОС и архитектуры**. На Linux потребуются системные зависимости Tauri (GTK3, WebKitGTK 4.1) и звуковые библиотеки, включая ALSA; на macOS — инструменты Xcode. Точный набор пакетов зависит от дистрибутива и выявляется при первой нативной сборке.

```bash
export VOSK_LIBRARY_DIR="/absolute/path/to/native/vosk"
bash tools/build-desktop.sh
bash tools/start-desktop.sh
```

Скрипт собирает оба исполняемых файла и запускает голосовое ядро вместе с GUI. Не запускайте второй экземпляр поверх первого. При закрытии GUI скрипт останавливает запущенное им ядро. Существующие release-ресурсы не перезаписываются: обновляйте их после резервного копирования настроек.

`JARVIS_RESOURCE_ROOT` позволяет указать каталог, **внутри которого лежит resources/**. Для macOS также предусмотрен поиск в `Contents/Resources`. Скрипт создаёт обычные исполняемые файлы, не готовый подписанный `.app` или установщик.

Для Silero можно задать `JARVIS_TTS_PYTHON` — абсолютный путь к Python с нужными зависимостями. Если нейроозвучка недоступна, резервный вариант: `say` на macOS, `espeak-ng` или `espeak` на Linux. Локальный Windows-runtime S2 не запускается на Unix. Перенос обученных голосов отдельно не подтверждён.

На Mac разрешите доступ к микрофону. Для GUI добавлено описание назначения разрешения; для запуска ядра из терминала могут понадобиться отдельные разрешения терминалу/исполняемому файлу.

## Установочные пакеты Linux и macOS

### Для пользователей

Не нужно устанавливать Rust, Node.js или Python для запуска готового пакета. Нужен **успешно собранный пакет своей ОС и архитектуры**; до его публикации в Releases этот путь недоступен. Экспериментальные сборки из Actions не равнозначны проверенному релизу.

- Ubuntu 24.04 / совместимый Debian x64 с glibc ≥ 2.39: скачайте `.deb`, откройте его в менеджере приложений либо выполните `sudo apt install ./имя-файла.deb`. Пакет устанавливает системные зависимости, включая WebKitGTK, резервную озвучку espeak-ng, уведомления и инструменты буфера обмена Wayland/X11. Ubuntu 22.04 и Debian 12 не поддерживаются этим рецептом. Запускайте JARVIS из меню приложений, не от root.
- Другие Linux x64: AppImage запускается после `chmod +x имя-файла.AppImage`. Нужна совместимая 64-битная система с glibc не ниже 2.39; рецепт собирается на Ubuntu 24.04, Ubuntu 22.04 и более старые системы не заявлены. Это не обещание работы на каждом дистрибутиве. Если отсутствует FUSE, попробуйте `./имя-файла.AppImage --appimage-extract-and-run`. Для системной озвучки установите espeak-ng через менеджер пакетов своей ОС.
- Mac: скачайте `.dmg` своей архитектуры (Intel либо Apple Silicon), откройте и перенесите JARVIS ALTRON в Applications. Для микрофона разрешите доступ в «Системные настройки → Конфиденциальность и безопасность → Микрофон». Сборка пока без Developer ID и нотариализации: Gatekeeper может блокировать запуск. Не отключайте защиту системы глобально; проверяйте источник пакета и используйте разрешение конкретного приложения в настройках безопасности, если доверяете ему.

Первый запуск открывает GUI и автоматически запускает вложенное голосовое ядро; закрытие приложения останавливает только запущенное им ядро. Модели Vosk, звуки и ресурсы входят в пакет. Ключи API и данные пользователя не входят. Microsoft 365 остаётся экспериментальным; Kerio и классический Outlook доступны **только в Windows** и скрыты на других ОС.

### Для разработчиков

Собирайте нативно: Linux-пакеты на Linux, macOS-пакеты на Mac. На Mac Intel и Apple Silicon выпускаются отдельные сборки; универсальную сборку не заявляем.

Ubuntu 24.04 (пример установки инструментов сборки; текущие бинарные зависимости ONNX Runtime требуют новую glibc):

```bash
sudo apt update
sudo apt install build-essential curl wget file libssl-dev libwebkit2gtk-4.1-dev \
  libgtk-3-dev libasound2-dev librsvg2-dev libayatana-appindicator3-dev \
  patchelf espeak-ng xdg-utils libnotify-bin python3 python3-pip
```

Дополнительно установите актуальный стабильный Rust через rustup и Node.js 22 с npm. Для буфера обмена в Lua: `wl-clipboard` на Wayland, `xclip` либо `xsel` на X11. Уведомления Lua используют `notify-send`.

При использовании AppImage эти внешние инструменты устанавливаются через менеджер пакетов дистрибутива: `espeak-ng`, `xdg-utils`, `libnotify-bin`, а для буфера обмена — `wl-clipboard` либо `xclip`. В `.deb` они уже указаны как зависимости.

На macOS установите Xcode Command Line Tools (`xcode-select --install`), стабильный Rust, Node.js 22 и Python 3 с pip. Системная резервная озвучка использует встроенный `say`. Нативные приложения Telegram, Discord, VS Code и Steam необходимо установить отдельно.

В корне проекта:

```bash
bash tools/package-desktop.sh
```

Скрипт загрузит только wheel Vosk своей платформы (Linux 0.3.45, Mac universal2 0.3.42), извлечёт нативную библиотеку в `target/`, соберёт голосовое ядро и упакует приложение штатным Tauri. Python-пакеты не устанавливаются в систему. Можно вместо загрузки задать `VOSK_LIBRARY_DIR` с собственной совместимой библиотекой. Нужен интернет для зависимостей и первой сборки.

Для Mac Intel скрипт дополнительно загружает официальный ONNX Runtime 1.23.2 из Microsoft GitHub Releases, проверяет SHA-256 и включает библиотеку, лицензию и уведомления в `.app`. Это сохраняет локальные нейросетевые функции: они не отключаются ради успешной компиляции. При ручной сборке без скрипта задайте `ORT_LIB_LOCATION` на каталог `lib` этого архива и `ORT_PREFER_DYNAMIC_LINK=1`; динамическая библиотека должна быть доступна загрузчику при запуске.

Пакеты появятся в `target/release/bundle/deb`, `appimage` или `dmg`. Нативная библиотека и ядро вложены в пакет; Windows DLL и Speak.exe не требуются. Изменять установленные ресурсы не нужно: настройки и логи записываются в пользовательский каталог проекта, а не в системную папку приложения.

### Автоматическая проверка

`.github/workflows/desktop-unix.yml` позволяет вручную собрать Linux x64, Mac Intel и Mac Apple Silicon через GitHub Actions. Пакеты сохраняются как артефакты успешного запуска, но workflow не публикует и не заменяет релиз автоматически. Сборка проверяет ресурсы и тесты платформенных путей; без физического микрофона она не подтверждает голосовое управление.

До объявления поддержки проверьте на каждой системе: установку → запуск из меню → микрофон → «Джарвис, открой браузер» → озвучку → заметку → таймер/напоминание → импорт/экспорт DOCX → агента → закрытие и повторный запуск. Проверьте сохранение данных после обновления. Для Mac отдельно Intel и Apple Silicon; для Linux отдельно X11 и Wayland. Автоматизация чужих окон через AutoHotkey не переносится; Windows-only сценарии скрыты, а не запускаются через Wine.

### Ограничения и первый тест

- Классический Outlook/Kerio через COM — только Windows. Microsoft 365 остаётся отдельным экспериментальным HTTP-подключением, требующим собственной проверки.
- Не проверены нативная сборка, микрофон/Vosk, горячие клавиши, уведомления, Clipboard, Lua-сценарии и упаковка.
- Проверяйте последовательно: запуск GUI → текстовая команда → микрофон → озвучка → открытие сайта → заметка → таймер. Почту проверяйте последней, без автоматической отправки.
- Зафиксируйте ОС, архитектуру и полный текст первой ошибки. Не публикуйте ключи, пароли и документы.

# Экспериментальная адаптация платформ

Это подготовка исходников, а не подтверждённая поддержка новых ОС. Linux/macOS не собирались на соответствующих машинах; Android не запускался на устройстве. Windows остаётся основной проверенной средой.

## Linux и macOS

Общими остаются Rust-ядро, интерфейс Tauri/Svelte и данные Центра. Добавлены поиск ресурсов вне Windows, выбор нативной библиотеки Vosk, системная озвучка и открытие файлов в проводнике. Сайты открываются через `xdg-open` / `open`. Команды Calculator, Telegram, Discord, VS Code и Steam используют платформенные варианты; приложение должно быть установлено. На Linux калькулятор требует `gnome-calculator`.

Windows-сценарии AutoHotkey, завершение процессов через taskkill и известные Windows-only команды исключаются из каталога на других ОС. Это не делает все оставшиеся сценарии автоматически переносимыми.

### Подготовка и запуск

Нужны Rust/Cargo, Node.js/npm, инструменты нативной сборки и **Vosk для своей ОС и архитектуры**. На Linux потребуются системные зависимости Tauri (GTK3, WebKitGTK 4.1) и звуковые библиотеки, включая ALSA; на macOS — инструменты Xcode. Точный набор пакетов зависит от дистрибутива и выявляется при первой нативной сборке.

```bash
export VOSK_LIBRARY_DIR="/absolute/path/to/native/vosk"
bash tools/build-desktop.sh
bash tools/start-desktop.sh
```

Скрипт собирает оба исполняемых файла и запускает голосовое ядро вместе с GUI. Не запускайте второй экземпляр поверх первого. При закрытии GUI скрипт останавливает запущенное им ядро. Существующие release-ресурсы не перезаписываются: обновляйте их после резервного копирования настроек.

`JARVIS_RESOURCE_ROOT` позволяет указать каталог, **внутри которого лежит resources/**. Для macOS также предусмотрен поиск в `Contents/Resources`. Скрипт создаёт обычные исполняемые файлы, не готовый подписанный `.app` или установщик.

Для Silero можно задать `JARVIS_TTS_PYTHON` — абсолютный путь к Python с нужными зависимостями. Если нейроозвучка недоступна, резервный вариант: `say` на macOS, `espeak-ng` или `espeak` на Linux. Локальный Windows-runtime S2 не запускается на Unix. Перенос обученных голосов отдельно не подтверждён.

На Mac разрешите доступ к микрофону. Для GUI добавлено описание назначения разрешения; для запуска ядра из терминала могут понадобиться отдельные разрешения терминалу/исполняемому файлу.

### Ограничения и первый тест

- Классический Outlook/Kerio через COM — только Windows. Microsoft 365 остаётся отдельным экспериментальным HTTP-подключением, требующим собственной проверки.
- Не проверены нативная сборка, микрофон/Vosk, горячие клавиши, уведомления, Clipboard, Lua-сценарии и упаковка.
- Проверяйте последовательно: запуск GUI → текстовая команда → микрофон → озвучка → открытие сайта → заметка → таймер. Почту проверяйте последней, без автоматической отправки.
- Зафиксируйте ОС, архитектуру и полный текст первой ошибки. Не публикуйте ключи, пароли и документы.

## Android

Отдельный облегчённый проект: [Mobile LAB](../mobile/android/README.md). Он не использует настольный голосовой движок и не обещает управление чужими окнами. Нет фонового прослушивания, Outlook COM, настольных агентов и синхронизации данных с ПК.

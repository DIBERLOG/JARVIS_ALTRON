# JARVIS 1.1.14 — домашняя сеть и понятные подсказки

## Причина сбоя

На снимке телефон обращался к `172.29.48.1:47832`. Проверка ПК показала: это интерфейс WSL, тогда как домашний Wi-Fi имеет адрес `192.168.1.77` и шлюз `192.168.1.1`. До исправления `lan_sync_addresses` возвращал все частные IPv4, сортируя строки. Интерфейс выбирал первый адрес, поэтому WSL оказался раньше Wi-Fi. VPN для воспроизведения этой ошибки не нужен.

## Изменения

- Windows получает свойства интерфейсов ОС: выбираются только активные физические адаптеры с частным IPv4. Подключение со шлюзом имеет приоритет, затем учитывается метрика. Повторы исключены.
- Виртуальные адаптеры WSL, VMware и VPN не предлагаются для QR-кода; проверка перед запуском сервера применяет тот же список.
- Обнаружение адресов и запуск обмена выполняются вне потока интерфейса. Время обнаружения ограничено 20 секундами; при ошибке не используется заведомо неподходящий виртуальный адрес. Во время поиска показывается понятный статус.
- На ПК памятка свёрнута и сокращена до подключения и подтверждения. Убраны технические пути, описание тестового профиля и внутренние термины из основных подсказок.
- На телефоне раздел «Как работает синхронизация» объясняет три направления обмена вместо заданий с тестовыми заметками. Подсказки об автообмене, резервных копиях, задачах и защите данных сокращены.
- Обычная ошибка тайм-аута предлагает включить обмен и обновить QR-код. Сообщение о VPN сохранено только для отказа Android в привязке соединения к сети.
- Данные, шифрование, сохранённые устройства и подтверждение с двух сторон сохранены.

## Установка

ПК: обновляется существующий `artifacts/sync-v2-lab/windows-1.1.0-instructions/JARVIS-Sync-v2-LAB.exe`, поэтому путь правила брандмауэра сохраняется. После перезапуска включите обмен и сканируйте новый QR-код. Старый содержит неверный адрес WSL.

Android: установите `artifacts/sync-v2-lab/JARVIS-Mobile-1.1.14-Sync-v2-LAB.apk` поверх предыдущего LAB. versionCode 17, версия `1.1.14-sync-v2-lab`, 6 990 881 байт.

## Проверки

- На реальном ПК read-only обнаружение через штатный Windows PowerShell возвращает физический домашний Wi-Fi `192.168.1.77`; WSL помечен виртуальным. Тестовые подключения к реальному профилю не создавались.
- Android release и lintRelease успешны; инструментальный прогон `OK (49 tests)`, 46 выполнены, три проверки требуют отдельных фикстур и пропущены.
- Пять холодных запусков Android 15: процесс жив, экран открыт, FATAL EXCEPTION отсутствует.
- Экран с объяснением направлений проверен визуально на собственном эмуляторе.
- Frontend прошёл сборку и проверку Svelte; существующие предупреждения других компонентов сохранены.
- Windows release собран. Проверки LAN: восемь успешны, один отдельный Android wire-сценарий пропущен. Дополнительный native-тест с ожидаемым адресом `192.168.1.77` прошёл, то есть проверен результат полного Windows-обнаружения, а не только разбор JSON.

## Дополнительная проблема запуска ПК

После остановки существующего окна и новая, и прежняя сборки не смогли открыть зашифрованную группу. Ключ записи Windows для текущего пути профиля не аутентифицировал файл группы. Другой уже существующий ключ JARVIS в том же хранилище успешно аутентифицировал группу, `devices.json` и `tls.json`.

Локальный инструмент `crates/jarvis-core/examples/inspect_local_profile.rs` в явном режиме `--repair` исправил привязку: прежний ключ текущего пути сначала сохранён и проверен в отдельной записи Windows Credential Manager, затем установлен криптографически проверенный ключ. Секреты и расшифрованные значения не выводятся и не экспортируются. Шифрованные файлы профиля не заменялись, профиль не сбрасывался. Причина исходного несовпадения записей ключей не установлена.

После исправления выполнены два успешных запуска, включая повторное закрытие и открытие: настройки загружаются, окно JARVIS отображается. Актуальная настольная сборка установлена по прежнему пути; SHA-256 EXE `14552856bb0e9d10fd20b2a9f9d8948c6cf95f6a28ac384debe20986add7d2bf`. Предыдущий EXE сохранён рядом как `JARVIS-Sync-v2-LAB-before-home-network-fix.exe`.

Полный обмен с личным телефоном после обновления требует повторной проверки пользователем. Готовность сборки не означает, что реальные данные уже синхронизированы.
